# YourFem · съдържание

> **In English.** The signed articles the YourFem app shows, and the manifest it reads
> them by. Published from the author's working folder by `tools/publish.mjs`; nothing
> here is edited by hand. All rights reserved — see [`LICENSE`](LICENSE).

Тук стоят **само подписаните статии** — тези с медицински рецензент, дата на прегледа
и неизтекъл срок. Черновите остават при автора. Хранилището е публично, защото
текстовете са публични така или иначе; пази се не тайна, а **кое е истинско**.

## Какво има вътре

| Файл | Какво е |
|---|---|
| [`manifest.json`](manifest.json) | Списъкът: коя статия е публикувана, с `sha256` на файла ѝ, и коя е **оттеглена** (`revoked`). Приложението вярва само на него. |
| `articles/<id>.json` | Една статия: заглавие, трите слоя (за нея, за студент, за лекар), източниците и подписът. |
| `meaning/<модел>-r<n>/<id>.json` | Векторите на една статия — по един за всеки откъс от текста „За теб“ — по които приложението я намира **по смисъл**. Всеки файл е вписан в манифеста със `sha256`. |
| [`CHANGELOG.md`](CHANGELOG.md) | Какво е излязло при всяко публикуване. Пише го скриптът, не човек. |
| [`tools/publish.mjs`](tools/publish.mjs) | Портата от работната папка на автора дотук. |
| [`tools/meaning.mjs`](tools/meaning.mjs) | Стъпката след портата: смята векторите на новото и промененото. |

Адресът, от който приложението чете: `https://yourfem.github.io/content/manifest.json`.

## Как се публикува

**Двойно щракване върху [`PUBLIKUVAY.cmd`](PUBLIKUVAY.cmd).** Той:

1. тегли последната версия от GitHub;
2. пита **защо** — „поправена доза желязо“ (по желание; какво се е променило, скриптът
   знае сам);
3. пуска портата, която показва какво ще излезе и пита:

   ```
   Нови: 2 · Променени: 1 · Оттеглени: 0 · Без промяна: 45
   Публикувам? (д или y = да)
   ```

4. смята **векторите** на новите и променените откъси (виж по-долу);
5. комитва и качва. `CHANGELOG.md` казва какво е излязло.

`articles.json` се търси в `%USERPROFILE%\Dropbox\mvp\app\data\`. Ако е другаде —
провлачи файла върху `PUBLIKUVAY.cmd` или задай `YOURFEM_ARTICLES` веднъж.
Източникът **само се чете**: нищо в Dropbox не се променя и не се трие.

**Веднъж, преди първия път:** Node.js и git на компютъра, членство в организацията
`YourFem` с право за запис, и `git clone https://github.com/YourFem/content.git` в
папка **извън** Dropbox — там стоят git входът и `node_modules`, а Dropbox е споделен.
За векторите, също веднъж: `npm install`, после `npm run meaning:setup`.

Без `.cmd`, на ръка:

```bash
npm install
node tools/publish.mjs "<път до>/mvp/app/data/articles.json" --note "защо"
npm run meaning:index
git add -A && git commit -m "Publish from the author's articles" && git push
```

Без терминал (скрипт или агент) портата не пита: без `--yes` показва какво ще излезе и
спира, без да запише; с `--yes` записва.

## Векторите за търсене по смисъл

Приложението намира статия и когато въпросът не споделя нито една дума със заглавието ѝ
— „може ли еспресо сутрин“ намира „Кафето е забранено напълно.“. За това всеки откъс от
текста „За теб“ има **вектор**. Смятат се тук, при публикуването, за да пътуват със
статията: иначе нова статия се намира по смисъл чак след обновяване на приложението.

| Команда | Какво прави |
|---|---|
| `npm run meaning:setup` | **Веднъж на компютър.** Слага зависимостите на модела (около 0,5 GB) и сваля модела от release-а на това хранилище (около 0,6 GB), като проверява `sha256` на всеки файл. Пуснат пак, продължава оттам, докъдето е стигнал. |
| `npm run meaning:index` | Смята вектор само за откъсите, чийто текст е нов. `PUBLIKUVAY.cmd` го пуска сам. |
| `npm run meaning:check` | Без модел: има ли всяка статия векторите на текста, който има сега. |
| `npm run meaning:selftest` | Смята един откъс наново и го сравнява с вектора му в хранилището: дава ли моделът на този компютър същите числа. Пуска се веднъж след `meaning:setup`. |

Четири неща, които държат това безопасно:

1. **Текстът не чака векторите.** Ако моделът липсва или стъпката падне, статиите и
   оттеглянията се публикуват все така, а изходът казва кои статии са без вектори. Такава
   статия се намира по заглавие, докато следващо пускане я настигне.
2. **Смята се само промененото.** Откъсът се познава по отпечатъка на текста си; който
   вече има вектор, го запазва. Нова статия е десетина откъса.
3. **Моделът е точно този на телефона.** Сваля се от release-а тук и се проверява по
   същите хешове, по които го проверява приложението. Вектори от друго копие на модела не
   са сравними с тези, които телефонът смята за нейния въпрос.
4. **Правилото за рязане е на приложението.** `tools/meaning/rule.mjs` и
   `tools/meaning/model.json` са **генерирани** от кода на приложението и не се редактират
   тук. Приложението ползва вектор само ако откъсът, който само реже, има същия отпечатък
   — редакция на място не променя какво прави то, а само прави всеки следващ вектор
   неизползваем, без да каже.

Моделът стои в `tools/meaning/.model/` и не влиза в git.

## Трите правила на портата

1. **Минава само подписано.** Липсващ рецензент, дата или изтекъл преглед — статията
   остава при автора.
2. **Махната статия се оттегля, не се трие.** Влиза в `revoked` и изчезва от всеки
   телефон при следващата му проверка, включително от такъв, който е бил офлайн.
3. **Текст, променен без нов подпис, се задържа.** Излиза подписаната версия, а скриптът
   казва коя статия чака нов подпис. Промяна извън медицинския текст (например клъстер)
   минава нормално.

Тестовете: `npm test`.
